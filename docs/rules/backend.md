# 后端开发规范

## 技术栈

- **语言**：Python（语法兼容 3.10+，开发用解释器版本锁定于 `backend/.python-version`，当前为 3.14）
- **模型 SDK**：openai、anthropic（使用厂商官方 SDK，依赖声明见 `backend/pyproject.toml`，锁定版本见 `backend/uv.lock`）
- **参数校验**：jsonschema（校验工具调用参数）
- **测试**：pytest + pytest-asyncio（异步测试无需额外标记；pytest 配置位于 `backend/pyproject.toml`）
- **类型检查**：basedpyright（standard 模式，配置位于 `backend/pyproject.toml`）
- **代码规范**：ruff（lint + 格式化，配置位于 `backend/pyproject.toml`）
- **环境配置**：python-dotenv（API 密钥存放于 `.env`，该文件不纳入版本管理）

## 目标架构

目前正在开发计划中，以下为终态愿景。

包含以下功能层：

1. **core — 基础定义层**：是为所有层服务的最底层依赖，定义了消息格式、工具接口、事件广播等基础格式。该层的设计应当精简，且功能均为全局服务，针对某一层的内容不应放置在此，而应当放置在对应功能层。
2. **models — 模型调用层**：负责与各家大模型 API 通信。每种 API 协议对应一个实现（如 OpenAI 兼容协议、Anthropic 协议），屏蔽厂商之间的字段差异，对上提供统一的调用方式。
3. **tools — 工具执行层**：负责工具的注册、参数校验与执行。提供注册表、校验器、执行器等机制；具体工具（如读文件、执行命令）是另行注册的内容，与机制分离。
4. **runtime — 运行时引擎层**：负责驱动 Agent 的主循环——组装上下文、调用模型、处理工具调用、记录历史，直到任务完成。同时提供事件总线、历史存取等运行期基础设施。
5. **security — 安全防护层**：负责工具执行前的权限检查。危险操作（写文件、执行命令等）在此被拦截，等待用户批准后放行。
6. **memory — 记忆子系统**：负责会话历史的持久化与恢复，使 Agent 重启后仍能延续此前的对话。
7. **mcp — MCP 集成层**：负责接入 MCP 协议的外部工具服务，管理 MCP 连接的完整生命周期，并对传输层作适配。
8. **reliability — 可靠性层**：负责结构化日志、分布式追踪、重试与熔断、监控与告警、敏感信息脱敏。
9. **orchestration — 编排引擎**：负责多 Agent、多步骤任务的分解与调度。
10. **application — 组合根**：应用的组装入口，负责读取配置、创建各层实例并互相连接，是唯一了解全局接线的地方。

相关代码位于 `backend/src/`，某一功能层相关代码写于 `backend/src/<层名称>` 下，尚未开发的部分可能不存在相应目录。

后端包含测试文件，位于 `backend/test`，某一功能层的相关测试文件写于 `backend/test/<层名称>` 下。

## 开发规范

### 依赖方向

- 除了 application 组合根，所有功能层**只允许依赖 core**，功能层之间不允许直接互相依赖；core 不依赖任何其他层。
- 各层之间的协作通过 core 中定义的抽象接口进行：调用方只认识接口，不认识具体实现。
- 实现与接口的连接只发生在 application 层；新增模块的合法改动是新增文件并在入口处接线，而不是改动既有模块的内部逻辑。

### 代码风格

- 文档字符串、注释一律使用中文，但保留必要的英文术语；标识符与协议字段名保持英文原文。
- 公开接口必须标注类型；可空值使用 `X | None` 写法。
- 数据结构优先使用 `@dataclass`；列表、字典等可变默认值通过 `field(default_factory=...)` 设置。

## 规范

- 每个模块在文件顶部写明职责范围，使用 docstring 样式。
- 执行完全严格的类型注解，除非必要不使用 `# type: ignore` 等方式忽略掉类型错误。
- 遵循 RUFF 代码规范。
- 异步优先原则，禁止同步阻塞；确实需要同步调用的走 `asyncio.to_thread`。
- 相似职责的代码放在同一文件中，同样适用于增量开发；仅当总线将来长出多种机制，文件过大时再考虑拆分，一般认为代码超过 300 行时视作文件过大。
- 进行增量开发时，同步更新测试文件，确保新增功能有对应的全量测试覆盖。
- 完成开发前运行 `poe check`，确保 lint、格式、类型检查、测试全部通过。

### 测试组织

- 打桩点设在 SDK 边界（如 `client.*.create`），离线测试不联网、不消耗 API 额度。
- 测试替身与工厂函数放在 `backend/test/fakes.py`（普通模块，显式 import 使用）；fixture 放在 conftest.py——仅某目录使用的放该目录的 conftest.py，跨目录共享的放 `backend/test/` 根下。
- 测试需要给 Provider 附加打桩属性（如请求捕获器）时，定义带属性声明的 Stub 子类，不直接在实例上动态挂属性（类型检查不可见）。
